# System Patterns

## Architecture Overview
The motor control system follows a layered architecture pattern with clear separation of concerns:

```
Application Layer
├── Motor Manager (motor_manager.cpp)
├── FOC Control (FOC.cpp)
└── Trajectory Planning (trap_traj.cpp)

Hardware Abstraction Layer
├── HAL Interface (HAL_PWM.cpp, drv8323.cpp)
├── Sensor Abstraction (base_encoder.h)
└── ADC Sampling (adc_multi_sample.h)

Platform Layer
├── STM32H7 HAL Drivers
├── FreeRTOS Kernel
└── Hardware Peripherals
```

## Core Design Patterns

### 1. Hardware Abstraction Pattern
**Location**: `HAL_interface/` folder
- **HAL_PWM.cpp**: PWM generation abstraction
- **drv8323.cpp**: Motor driver IC interface
- **Pattern**: Encapsulates hardware-specific implementations behind clean interfaces

### 2. Sensor Strategy Pattern
**Location**: `Encoder/` folder
- **base_encoder.h**: Abstract encoder interface
- **ABEncoder.cpp**: Incremental encoder implementation
- **HallSensor_encoder.h**: Hall sensor implementation
- **fake_encoder.h**: Test/simulation encoder
- **Pattern**: Interchangeable sensor implementations through common interface

### 3. Control Algorithm Composition
**Location**: `FOC/` folder
- **FOC.cpp**: Field-Oriented Control implementation
- **PID.h**: PID controller components
- **testing.cpp**: Algorithm validation
- **Pattern**: Composable control algorithms with testable components

### 4. Real-Time Task Management
**Location**: `Core/Src/freertos.cpp`
- **Pattern**: FreeRTOS tasks for time-critical motor control
- **Priority-based scheduling**: Ensures control loop timing
- **Inter-task communication**: Queues and semaphores for coordination

### 5. Manager/Controller Pattern
**Location**: `Motor/` folder
- **motor_manager.cpp**: High-level motor coordination
- **Motor.cpp**: Individual motor control
- **Pattern**: Manager orchestrates multiple motor controllers

## Component Relationships

### Control Flow
```
Motor Manager → FOC Controller → HAL_PWM → DRV8323 → Motor
     ↑              ↑              ↑
Trajectory    Encoder Feedback   ADC Sensing
```

### Data Flow
1. **Sensor Data**: Encoders → FOC Controller
2. **Control Signals**: FOC → HAL_PWM → Motor Driver
3. **Feedback**: ADC → Current/Voltage monitoring → FOC
4. **Commands**: Motor Manager → Individual Motors

## Key Technical Decisions

### 1. Mixed C/C++ Architecture
- **C++**: Application logic, classes, and algorithms
- **C**: STM32 HAL integration and low-level drivers
- **Rationale**: Leverages STM32 ecosystem while enabling OOP design

### 2. Real-Time Constraints
- **FreeRTOS**: Deterministic task scheduling
- **High-frequency control loops**: FOC at >10kHz
- **Priority assignment**: Critical control tasks have highest priority

### 3. Modular Sensor Support
- **Abstract interfaces**: Enable different encoder types
- **Runtime polymorphism**: Sensor selection at initialization
- **Testability**: Fake sensors for unit testing

### 4. Hardware Driver Isolation
- **HAL layer**: Isolates hardware dependencies
- **Driver classes**: Object-oriented hardware interfaces
- **Configuration**: Parameter-driven setup

## Code Organization Principles

### File Naming Convention
- **Headers**: `.h` for C interfaces, mixed for C++
- **Implementation**: `.cpp` for C++, `.c` for C HAL code
- **Modules**: Folder per major component

### Build System
- **Make-based**: Generated by STM32CubeIDE
- **Dependency tracking**: Automatic rebuilds
- **Debug support**: Symbol generation and optimization control

### Memory Management
- **Static allocation**: Preferred for real-time systems
- **Stack management**: FreeRTOS task stacks
- **Peripheral memory**: Memory-mapped hardware access

## Integration Patterns

### STM32 HAL Integration
- **Peripheral initialization**: STM32CubeMX generated code
- **Interrupt handling**: HAL callbacks to application
- **Clock configuration**: System-level timing setup

### FreeRTOS Integration
- **Task creation**: Separate tasks for control loops
- **Synchronization**: Semaphores for critical sections
- **Communication**: Queues for inter-task messaging

## Testing Strategies
- **Unit testing**: Component-level validation
- **Hardware-in-loop**: Real motor testing
- **Simulation**: Fake encoders and drivers for testing
